# Project status — 2026-10-17

**Development version:** Existing TripShot Companion plus Service Updates; **18 stdio MCP tools**, with all 16 baseline signatures/defaults preserved. Work is confined to Projects. Original Downloads runtime and Secure MCP Tunnel untouched; no remote, deployment, cloud infrastructure, or scheduler.

**Capabilities:** Read-only Loop/Intercampus retrieval; imported 50-stop catalog; reported vs scheduled ETAs and conservative confidence/direction labels; midnight service-day coverage; full four-direction published 2026–27 timetables; future departures, same-vehicle journeys and straight-line nearby-stop planning; on-demand timetable refresh. Service Updates now add official notice evidence, independent revisions, explicit uncertainty, current/future departure annotations and confirmed-disruption journey filtering. Original schedule/ETA records and matching counts remain available.

**Service Updates policy:** 15-minute success TTL; error retries at 5/10/20/40/60 minutes; force refresh; no background work. Validated atomic cache and OS lock, last-known-good fallback/history, finite retention and developer rollback. Removed notices stay unconfirmed; absent notices or refresh failures never confirm normal operation. Unknown years/dates/stops/directions/effects are not guessed. Special-service announcements are surfaced without invented departures.

**Verified:** **105 regressions passed**, including all automated SU01–SU21 acceptance scenarios, reliability fixes and domain/transport integration tests. Real local MCP smoke: 18 names, protocol 2026-07-28, synthetic ride plus cached Service Updates calls. Python 3.14.7 / MCP 2.3.0 / tzdata 2026.5; dependency check clean; no dependency changes. Actual official Service Updates HTML validated in an isolated temporary cache and yielded three notices. Earlier migration verified both TripShot route requests and all four official timetable pages.

**Fixed prerequisites:** Scheduled future MCP/CLI queries no longer require live-source configuration. Invalid location-plan dates propagate structured errors. Malformed timetable caches fall back to validated history/bundled data instead of failing on bad structure/timestamps.

**October 16 example:** Offline demonstration retains Central L (EB)'s 16:32 published departure. Missing year leaves it uncertain with provisional journeys. Explicit 2026 fixture review marks it unavailable and excludes all eight matching journeys, retaining original evidence. The actual source omits the year; no production interpretation was silently created. [Run/review details](docs/SERVICE_UPDATES_IMPLEMENTATION.md).

**Limitations:** English pattern coverage and stop-family mappings are deliberately finite. Unknown variants, unclear end boundaries, changed wording and the Patten Gym temporary terminus require review. Chicago Express has announcements but no modeled timetable. Bundled calendars/hours remain fixed; timetable cache multi-process transactions remain separate future work. No transfers, routed walking/accessibility, GPS prediction accuracy, realized arrivals, continuous availability or live ChatGPT tunnel revalidation was established.

**Next priority:** Product-owner review of sample outputs and explicit year/stop/terminus interpretations, then expand mappings/patterns where useful. Review any production connection/deployment changes separately.
